# مُنزل الفيديوهات المحلي — Flask + yt-dlp

واجهة الهاتف موجودة بالكامل في `templates/index.html`، ولا توجد مكتبات JavaScript خارجية.

يدعم المشروع حاليًا ثلاث منصات عبر محرك yt-dlp نفسه: **YouTube**، **TikTok**، و**Instagram**.

## التشغيل في Termux

```bash
pkg update
pkg install python ffmpeg
pip install -r requirements.txt
python app.py
```

افتح المتصفح على:

`http://127.0.0.1:5000`

## المنصات المدعومة والروابط المقبولة

النظام يتعرف على المنصة من نطاق الرابط نفسه (وليس من كلمات داخل الرابط)، عبر قائمة نطاقات مسموحة صريحة لكل منصة. أي نطاق خارج هذه القوائم يُرفض برسالة "الرابط غير صالح أو المنصة غير مدعومة."، حتى لو كان yt-dlp يدعمه تقنيًا.

**YouTube** — `youtube.com`، `www.youtube.com`، `m.youtube.com`، `music.youtube.com`، `youtu.be`، `youtube-nocookie.com`
مثال: `https://www.youtube.com/watch?v=XXXXXXXXXXX` أو `https://youtu.be/XXXXXXXXXXX`

**TikTok** — `tiktok.com`، `www.tiktok.com`، `m.tiktok.com`، `vm.tiktok.com`، `vt.tiktok.com`
مثال: `https://www.tiktok.com/@username/video/1234567890123456789`

**Instagram** — `instagram.com`، `www.instagram.com`، `instagr.am`، `www.instagr.am`
مثال: `https://www.instagram.com/reel/XXXXXXXXXXX/` (Reels والمنشورات المفردة التي تحتوي فيديو)

يمكن تخصيص أي من هذه القوائم عبر متغيرات البيئة `YOUTUBE_ALLOWED_HOSTS`، `TIKTOK_ALLOWED_HOSTS`، `INSTAGRAM_ALLOWED_HOSTS` (قيم مفصولة بفواصل).

### قيود مهمة على TikTok وInstagram

- **لا** كل رابط TikTok يعمل بالضرورة، و**لا** كل رابط Instagram يعمل بالضرورة — هاتان المنصتان تُغيّران آليات الحماية والوصول باستمرار، وyt-dlp يلاحقهما بتحديثات دورية.
- المحتوى الخاص (private)، المحذوف، أو الذي يتطلب تسجيل دخول لن يكون متاحًا للتنزيل، وستظهر رسالة عربية واضحة تشرح السبب المحتمل بدل توقف الواجهة أو ظهور خطأ تقني.
- بعض فيديوهات TikTok/Instagram لا تحتوي أيًا من دقات الفيديو القياسية الست (1080/720/480/360/240/144). في هذه الحالة تعرض الواجهة الجودة الفعلية المتاحة كما هي (بارتفاعها الحقيقي، دون التظاهر أنها إحدى الدقات القياسية) بدل ترك المستخدم بلا أي خيار تنزيل.
- إذا حدّثت TikTok أو Instagram آلية عملها بما يكسر استخراج yt-dlp الحالي، فالحل الوحيد هو تحديث حزمة `yt-dlp` نفسها (`pip install -U yt-dlp`)، وليس تعديل هذا المشروع.

### دعم YouTube الحالي

الإصدار المطلوب من yt-dlp مثبت عبر مجموعة `default` حتى يتم توفير مكونات EJS اللازمة لدعم YouTube بشكل كامل. كما يحتاج yt-dlp إلى JavaScript runtime خارجي؛ Deno هو الخيار المفضل، ويمكن استخدام Node.js 22+ كبديل عند توفره. المشروع يكتشف runtime الموجود في `PATH` تلقائيًا ولا يثبت أي runtime أثناء التشغيل. يمكن تحديد runtime يدويًا عبر `YTDLP_JS_RUNTIME=node` أو `YTDLP_JS_RUNTIME=deno:/path/to/deno`.

مثال اختياري في Termux عند توفر الحزمة:

```bash
pkg install deno
```

أو يمكن استخدام Node.js 22+ عند توفره:

```bash
pkg install nodejs
```

## مجلد التنزيلات

افتراضيًا تُحفظ الملفات في:

`/storage/emulated/0/Download/VideoDownloader`

وهذا مجلد مخصص للمشروع حتى لا يعرض السيرفر ملفات أخرى موجودة في مجلد Downloads العام. يمكن تغيير المسار عبر متغير البيئة `DOWNLOADS_DIR`.

### اختيار YouTube player clients

افتراضيًا لا يفرض المشروع أي `player_client` حتى يترك yt-dlp يختار عملاء YouTube المناسبين تلقائيًا. هذا مهم لأن توفر الصيغ ومتطلبات PO Token تتغير مع الوقت. لا تستخدم `YTDLP_PLAYER_CLIENTS` إلا عند وجود سبب محدد للاختبار أو التخصيص.

```bash
YTDLP_PLAYER_CLIENTS="default,web_embedded" python app.py
```

لإتاحة السيرفر من جهاز آخر على الشبكة المحلية فقط عند الحاجة:

```bash
FLASK_HOST=0.0.0.0 python app.py
```

الافتراضي هو `127.0.0.1` لتقليل التعرض غير المقصود على الشبكة.

## جودة الفيديو في الواجهة

تعرض الواجهة ستة مستويات أساسية فقط: `144p` و`240p` و`360p` و`480p` و`720p` و`1080p`. يتم اختيار أفضل stream فعلي لكل مستوى من الصيغ التي ترجعها المنصة (YouTube، TikTok، أو Instagram)، مع تفضيل معدل إطارات أعلى عند توفره (مثل 1080p 60 FPS). الصيغ ذات الارتفاعات غير القياسية لا تظهر بديلًا لإحدى هذه الدقات ولا تُسمّى باسمها. الجودة الافتراضية المختارة عند جلب البيانات هي `720p` (أو أقرب جودة أقل متاحة) لتقليل زمن التنزيل واستهلاك البيانات؛ يمكن للمستخدم رفعها يدويًا لأي مستوى آخر بضغطة واحدة.

بعض فيديوهات TikTok وInstagram لا تحتوي أصلًا أيًا من هذه الدقات القياسية. في هذه الحالة فقط، تعرض الواجهة الجودة (أو الجودات) الفعلية المتاحة للفيديو بارتفاعها الحقيقي (مثل `640p`)، مع توضيح أنها "أقرب جودة متاحة" وليست إحدى الدقات القياسية الست.

## نقاط API

- `GET /api/health` — فحص yt-dlp وffmpeg وJavaScript runtime، ويتضمن أيضًا حقل `platforms: {youtube, tiktok, instagram}` يوضح أن extractor كل منصة مفعّل داخل yt-dlp في هذا الإصدار. هذا **لا** يضمن أن كل رابط أو فيديو من تلك المنصة سيعمل فعليًا.
- `POST /api/info` — يجلب معلومات الفيديو والصيغ المتاحة، ويتضمن الآن حقل `platform` (`youtube`/`tiktok`/`instagram`) ضمن بيانات الاستجابة.
- `POST /api/download` — يبدأ التنزيل.
- `GET /api/progress/<task_id>` — يعيد حالة التنزيل.
- `GET /downloads/<filename>` — يرسل الملف بعد اكتماله.

جميع الحقول الموجودة سابقًا في هذه النقاط ما زالت كما هي؛ الإضافات الجديدة (`platform`، `platforms`، `other_qualities`) حقول اختيارية إضافية فقط.

## رسائل الأخطاء الأساسية

كل خطأ متوقع يتحول إلى رسالة عربية واضحة بدل traceback أو رمز خطأ تقني. من أهم الرسائل:

| الحالة | الرسالة |
|---|---|
| رابط غير صالح أو من نطاق غير مدعوم | الرابط غير صالح أو المنصة غير مدعومة. |
| فيديو محذوف أو غير موجود | تعذّر العثور على الفيديو. ربما تم حذفه أو أصبح غير متاح، أو أنه محظور في منطقتك. |
| محتوى خاص/يتطلب تسجيل دخول (TikTok) | تعذر الوصول إلى هذا الفيديو من TikTok. قد يكون الفيديو خاصًا أو محذوفًا أو يتطلب صلاحيات إضافية. |
| محتوى خاص/يتطلب تسجيل دخول (Instagram) | هذا المحتوى من Instagram غير متاح للتنزيل حاليًا، أو يتطلب تسجيل الدخول. |
| مشكلة اتصال بالشبكة | تعذّر الاتصال بخدمة {المنصة}. تحقق من اتصال الإنترنت ثم أعد المحاولة. |
| انتهاء مهلة الاتصال | انتهت مهلة الاتصال. أعد المحاولة. |
| حظر مؤقت / rate limit من المنصة | الخدمة رفضت الطلبات مؤقتًا. انتظر قليلًا ثم أعد المحاولة. |
| صيغة الجودة المطلوبة لم تعد متاحة | الصيغة المطلوبة غير متاحة لهذا الفيديو. أعد جلب البيانات واختَر صيغة أخرى. |
| ffmpeg غير مثبت | يلزم تثبيت ffmpeg لإكمال هذه العملية. |
| مشكلة في التخزين | تعذّر حفظ الملف. تحقق من مساحة التخزين وصلاحيات مجلد التنزيل. |
| أي خطأ آخر غير متوقع | حدث خطأ غير متوقع أثناء معالجة الفيديو. |

تفاصيل الأخطاء التقنية (رسالة yt-dlp/ffmpeg الأصلية، traceback) تُسجَّل داخليًا فقط عبر `logging` للتشخيص، ولا تظهر في الواجهة أبدًا.

## حماية الملفات الكبيرة والدقات العالية

- **مساحة القرص**: يُرفض بدء التنزيل إذا كانت المساحة الحرة أقل من `MIN_FREE_DISK_MB` (الافتراضي 250MB). وأثناء التنزيل يُفحص المتبقي كل بضع ثوانٍ: إذا كان الحجم معروفًا فالمطلوب = المتبقي للتنزيل + هامش الأمان، ويُضاف حجم الملف مرة أخرى عند الحاجة لدمج ffmpeg (لأن الدمج ينتج نسخة جديدة مؤقتًا). عند الخطر يتوقف التنزيل برسالة واضحة وتبقى الملفات الجزئية لاستئنافها بعد تحرير المساحة.
- **أقصى حجم للملف**: `MAX_DOWNLOAD_MB` (الافتراضي 4096MB، والقيمة `0` تعني بلا حد). الفيديو الأكبر منه يُرفض برسالة تقترح جودة أقل. يعمل الفحص فقط عندما يكون الحجم معروفًا مسبقًا، وبعض مصادر TikTok/Instagram لا تعلن الحجم.
- **مهلات الشبكة**: مهلة 20 ثانية لجلب المعلومات، و60 ثانية أثناء التنزيل الفعلي، مع حتى 10 إعادات محاولة وتهدئة تصاعدية بينها، حتى لا يُقطع تنزيل كبير بسبب تباطؤ عابر في شبكة الهاتف.
- **ffmpeg**: الفيديو يُنسخ كما هو بلا إعادة ترميز (`stream copy`) ويُعاد ترميز الصوت فقط، مع تحديد عدد الخيوط بنصف أنوية المعالج (بحد أدنى 2) لتخفيف الحمل والحرارة.
- **الواجهة**: أثناء الدمج يظهر شريط متحرك وعدّاد ثوانٍ منقضية بدل نسبة ثابتة على 99%، ليتأكد المستخدم أن العملية تعمل.

متغيرات بيئة اختيارية: `MIN_FREE_DISK_MB`، `MAX_DOWNLOAD_MB`.

## خصائص الاستقرار والأداء

- تنزيل واحد فعّال في نفس الوقت، مع مهمة واحدة إضافية في الانتظار، لتقليل الضغط على الهواتف الضعيفة.
- لا يتم تشغيل أكثر من استخراج معلومات واحد في الوقت نفسه.
- استئناف التنزيلات الجزئية عند توفر ملفات مؤقتة.
- تنزيل أجزاء (fragments) الفيديو بالتوازي (حتى 4 في آنٍ واحد) لتسريع التحميل على الروابط المجزأة (DASH/HLS) دون إرهاق موارد الهاتف.
- تنظيف تلقائي لسجل المهام القديمة من الذاكرة.
- حدود على حجم الطلب، طول الرابط، ومعرّف الصيغة.
- التحقق من أن الروابط موجهة إلى نطاقات معروفة ومسموحة صراحةً (YouTube، TikTok، أو Instagram) عبر تحليل حقيقي للرابط (`urlsplit`)، وليس بحثًا عن كلمة داخله.
- استخدام `send_from_directory` ومسار تنزيل مخصص لتقليل مخاطر الوصول غير المقصود إلى ملفات أخرى.
- في دمج فيديو + صوت منفصلين: يبقى الفيديو `stream copy` بدون إعادة ترميز، بينما يُعاد ترميز الصوت إلى AAC مع معالجة timestamps لتقليل مشاكل تأخر/انحراف الصوت.
- الواجهة تقفل بدء تنزيل ثانٍ أثناء المهمة، وتستخدم استطلاعًا متدرجًا للحالة لتقليل استهلاك الشبكة والبطارية.
